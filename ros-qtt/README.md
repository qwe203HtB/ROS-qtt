# ROS-qtt

**Клиент [csqtt](https://github.com/amurcanov/csqtt) для MikroTik RouterOS.**
Форк порта клиента под MikroTik RouterOS: [ядро csqtt v2.5.0 © amurcanov](https://github.com/amurcanov/csqtt)
и упаковывает его как **контейнер RouterOS**, так что ваш роутер MikroTik сам
становится абонентом csqtt-туннеля — как телефон с приложением CSQTT, только
без телефонов: ключ кладётся в файл на диске роутера, и роутер
уходит в VK-TURN-туннель, замаскированный под медиатрафик звонка.

При каждом запуске ядро пишет строку авторства, она же попадает в `/log`
роутера:

```
ROS-qtt · by qwe203 · ядро: csqtt v2.5.0 © amurcanov (PolyForm-Noncommercial-1.0.0)
```

> ⚠️ **Лицензия.** Ядро csqtt — **PolyForm Noncommercial 1.0.0** (© amurcanov):
> использование строго некоммерческое. ROS-qtt наследует то же условие:
> же условие: для дома, для себя, для сообщества — можно; продавать/встраивать
> в платный сервис — нельзя.

## Как это работает

Роутер не умеет запускать сторонний софт напрямую — но с пакетом **container**
(RouterOS 7.5+) он умеет запускать контейнеры, и MikroTik отдаёт контейнерам
`/dev/net/tun` и root (user=0:0). Этого ровно хватает ядру csqtt (raw-IP TUN):

```
 ┌────────────────────────────── MikroTik RouterOS ────────────────────────────┐
 │  LAN-клиент → маршрут роутера → ros-qtt-br → контейнер ros-qtt              │
 │                                              ├─ ros-qtt  (ядро csqtt 2.5.0)│
 │                                              │   · raw-IP TUN rosqtt0      │
 │                                              │   · MTU 1300 как в приложении│
 │                                              │   · MASQ LAN-трафика → адрес│
 │                                              │     TUN (роутер = 1 учётка) │
 │                                              └─ tun-dispatch: TUN + fd    │
 │  veth контейнера → NAT → WAN  (UDP DTLS/TURN к серверу csqtt)               │
 └────────────────────────────────────────────────────────────────────────────┘
```

Роль «VpnService» приложения на Android здесь выполняет **tun-dispatch**
(приложение csqtt само не открывает `/dev/net/tun` — fd ему передают): хелпер
открывает `/dev/net/tun`, создаёт интерфейс `rosqtt0` и передаёт fd ядру через
абстрактный UDS — тем же каналом (`--tun-uds`), каким это делает приложение
CSQTT. Логика ядра — без единой правки: ровно апстрим v2.5.0 плюс
[`ros-qtt.patch`](ros-qtt.patch) (только авторская подпись и имя бинарника).

**Внутри контейнера** LAN-трафик MASQ-ится к адресу TUN-устройства: сервер
видит роутер как одного абонента со «своим» адресом — так же, как телефон в
приложении живёт под одним IP на всё устройство.

## Состав форка

| файл | что это |
|---|---|
| `ros-qtt.patch` | авторская подпись в старте ядра + переименование: ядро собирается как `ros-qtt`, версия `2.5.0-rosqtt.1` |
| `install-from-github.rsc` | **инсталлер одной командой**: качает образ из Releases, ключ — из `ROSQTTKey`/envlist (без флешки и файлов) |
| `build.sh` | сборка статического ядра (musl) из пина апстрима + патча (проверенный zigbuild-путь) |
| `tun-dispatch.c` | хелпер-«VpnService»: /dev/net/tun → TUNSETIFF rosqtt0 → fd по SCM_RIGHTS |
| `container/Dockerfile` · `container/entrypoint.sh` | образ RouterOS: alpine 3.21 + iptables; разбор ключа `csqtt://connect?…`, TUN, маршруты, MASQ |
| `install-ros-qtt.rsc` | идемпотентный инсталлер RouterOS (veth+bridge+NAT, контейнер, маршруты 0/1+128/1) |
| `ros-qtt.conf.example` | шаблон ключа/конфига |
| `pack.sh` | docker buildx + save → `ros-qtt-<arch>.tar` для роутера |

## Требования

- MikroTik **RouterOS ≥ 7.5** и пакет **container** (`.npk` архитектуры вашего
  роутера: arm64 / x86). Важно: MikroTik выпускает пакет container только для
  **arm, arm64 и x86** — устройства **mipsbe / mmips / smips НЕ поддерживаются**
  (на них пакет просто нет, контейнер и `/dev/net/tun` недоступны). Слабые
  arm32-устройства (например, hEX Refresh с EN7562CT) — вне этого рецепта:
  он собирает только amd64 и arm64. Если ваш текущий роутер — mipsbe, ROS-qtt
  нужен второй arm64/x86-бокс (или CHR на мини-ПК/VM) за ним.
- Разовая физическая активация: `/system/device-mode/update container=yes`
  и подтверждение кнопкой reset (или холодный ребут на x86).
- Диск/USB (примерно 200+ МБ свободно): контейнер, том и ключ на нём.
- Один ключ = один роутер: как и телефон, роутер — одно устройство туннеля.

## Установка одной командой (флешка не нужна)

Подключитесь к роутеру (Winbox → Terminal или ssh). Вставьте **ваш ключ**
(csqtt:// ссылка от панели) в кавычки шаблона и выполните:

```
:global ROSQTTKey "csqtt://connect?v=2&host=…&peer=…&password=…&hashes=…"; /tool fetch url="https://raw.githubusercontent.com/qwe203HtB/ROS-qtt/main/ros-qtt/install-from-github.rsc" dst-path=ros-qtt-from-github.rsc; /import file-name=ros-qtt-from-github.rsc
```

`install-from-github.rsc` всё делает сам:

1. качает с **Releases этого репозитория** образ `ros-qtt-<arch>.tar` под
   архитектуру роутера (amd64/arm64) — собирать образ не нужно;
2. передаёт ключ внутрь контейнера как переменную окружения `SOURCE`
   (`/container envs`) — файл с ключом не создаётся. Литеральный «+» в хешах
   должен быть записан как `%2B` — панель его так и отдаёт;
3. собирает сеть (veth/мост/NAT), контейнер и **маршруты полного туннеля**
   (все устройства роутера — см. ниже), запускает контейнер.

Смена ключа — та же команда с новым ROSQTTKey. Идемпотентно. Требования:
RouterOS ≥ 7.5, пакет `container` (Packages → .npk архитектуры) и разовое
подтверждение `/system/device-mode/update container=yes`.

Альтернатива: перетащить `ros-qtt.conf` в Winbox → Files → [диск]/ros-qtt/
(тоже без флешки) — скрипт смонтирует файл и не будет трогать envlist.
Если хочется собрать образ самому — «Установка за 3 шага» ниже.

## Установка за 3 шага (свой build)

Подробности каждого шага — в комментариях `install-ros-qtt.rsc` и в
`ros-qtt.conf.example`. Коротко:

**1. Соберите образ** (на любой Linux-машине с docker buildx; тот же шаг легко
переносится в CI):

```bash
bash build.sh dist arm64        # dist/ros-qtt-linux-arm64 + tun-dispatch-linux-arm64
bash pack.sh arm64 dist         # → ros-qtt-arm64.tar
```

**2. Залейте на роутер** (Winbox → Files) и положите ключ:

```
disk1/ros-qtt-arm64.tar               → переименуйте в disk1/ros-qtt.tar
disk1/ros-qtt/ros-qtt.conf            ← КЛЮЧ (см. ros-qtt.conf.example)
```

Ключ — это ссылка от панели (**Peers → копировать csqtt://connect ссылку**) или
поля `HOST/PEER_PORT/PASSWORD/HASHES` по отдельности. Хеши VK — TURN-креды:
ссылка от панели несёт их сама, экранирование `+`/`%` entrypoint разжимает.

**3. Импортируйте** `install-ros-qtt.rsc`, поправив ОПЦИИ сверху (диск, IP).

Смена ключа/хешей: переписали `ros-qtt.conf` → `/container stop ros-qtt` и
`/container start ros-qtt`. Пересборка контейнера не нужна.

## Установка одной командой

Смотрите раздел «Установка одной командой (флешка не нужна)» выше: теперь это
основной сценарий (`install-from-github.rsc` качает образ из Releases и ключ
передаёт в envlist, файлы не нужны). Путь, описанный в этом подразделе (предзалитые файлы +
install-ros-qtt.rsc), остался для собственных сборок:

- если образ и ключ уже лежат на диске (`disk1/ros-qtt.tar` и
  `disk1/ros-qtt/ros-qtt.conf`):

```
/tool fetch url="https://raw.githubusercontent.com/qwe203HtB/ROS-qtt/main/ros-qtt/install-ros-qtt.rsc" dst-path=install-ros-qtt.rsc; /import file-name=install-ros-qtt.rsc
```

Скрипт сам создаёт veth/мост/NAT, том конфига, контейнер, **добавляет маршруты
полного туннеля** и стартует контейнер. Повторный import ничего не дублирует
(идемпотентен).

## Кто ходит через туннель (режимы)

По умолчанию инсталлеры ставят режим **`devices` — через туннель ходят только
выбранные устройства**, остальной трафик роутера (в интернет и к самому
роутеру) идёт как раньше. Механика: `mark-routing` в отдельную таблицу
`ROSQTT-rt` (mangle по `src-address`) + маршрут `0.0.0.0/0` через контейнер
именно в этой таблице.

| Режим (`ROSQTTMode`) | Что уходит в туннель | Задать |
|---|---|---|
| `devices` (дефолт) | только выбранные **устройства** — по их IP/подсети | `ROSQTTDevices="192.168.8.20;192.168.8.0/24"` |
| `nets` | трафик к выбранным **сетям назначения** | `ROSQTTRoutesFor="192.168.20.0/24;10.55.0.0/16"` |
| `full` | все устройства роутера (как в 0.1.0) | — (дефолтные `0.0.0.0/1;128.0.0.0/1`) |

Для «одной команды» добавьте к ней перед `/import`:

```
:global ROSQTTMode "devices"; :global ROSQTTDevices "192.168.8.20;192.168.8.0/24";
```

Честно о границе: маршрутизация в RouterOS работает по IP/подсети — выбор
**отдельного приложения** на одном устройстве (один браузер — в туннель, другой
— нет) роутер сделать не может; разделяйте по устройствам, а внутри одного
устройства — средствами самого устройства. Локальные сети роутера всегда идут
мимо туннеля (обратные пути — `EXCLUDE_SUBNETS` в контейнере).

Откат любого режима:

```
/ip route remove [find where comment~"ROS-qtt"]
/ip firewall mangle remove [find where comment~"ROS-qtt"]
/routing table remove [find where name="ROSQTT-rt"]
```

## Режимы заворота трафика (ROSQTTMode)

Работа через инсталлеры, «Установка одной командой» выше: режим уже описан
там же (`devices`/`nets`/`full`). Подробности:

- **`devices` (по умолчанию)**: через туннель идёт только отмеченное
  устройство/подсеть (mangle `mark-routing` → таблица `ROSQTT-rt` → маршрут
  через контейнер только в этой таблице). Остальной трафик роутера не трогается.
- **`nets`**: в туннель заворачиваются сети назначения из `ROSQTTRoutesFor`
  (например, `192.168.20.0/24;10.55.0.0/16`); дефолт-маршрут и доступ к
  роутеру не трогаются. Убрать — удалите маршруты с комментарием `ROS-qtt …`.
- **`full`**: полный туннель (`0.0.0.0/1` + `128.0.0.0/1` через контейнер,
  дефолт списка `ROSQTTRoutesFor`) — все устройства, как в 0.1.0. Откат —
  удалить два маршрута с комментарием `ROS-qtt …`.
- выбрать отдельные **приложения** на одном устройстве роутером нельзя
  (маршрутизация — по IP); см. «Кто ходит через туннель» выше.

## Диагностика

```routeros
/container print                             # статус (extracting → stopped → running)
/log print where message~"ROS-qtt"           # подпись и сообщения ROS-qtt
/container/shell 0                           # внутри: ps, ip route, iptables -t nat -S
/ip route print where comment~"ROS-qtt"      # что завернуто
```

Частые причины молчаливого старта:

- **device-mode** не подтверждён физически — контейнеры запрещены вообще;
- статус надолго в `extracting` — медленный носитель; образ распаковывается
  один раз, подождите;
- `tun-dispatch: нет /dev/net/tun` — в старых сборках RouterOS контейнерам не
  отдавали tun; обновитесь (в современных сборках `/dev/net/tun` в списке /dev);
- ядро пишет `Нужен пароль в переменной CSQTT_PASSWORD` или `Нет хешей VK` —
  в `ros-qtt.conf` пустые PASSWORD/HASHES (ссылка распарсилась, но поля пусты);
- TURN вечно переконнекчивается — VK-хеши устарели: обновите их в панели,
  перепишите HASHES и перезапустите контейнер.

## Ограничения (честно)

- Роутер = **одно устройство** туннеля (как один телефон): весь LAN-трафик
  MASQ-ится под адрес TUN. Разводить отдельных абонентов через один ключ нельзя.
- csqtt-сервер новых версий (2.1.9-2+) кладёт в свой TUN только пакеты с
  источником = выданному адресу; MASQ в контейнере делает это условие
  выполненным — роутер всегда ходит под одним адресом TUN.
- Хеши VK стареют — их выдаёт панель у владельца сервера; у роутера нет
  приложения, где они обновляются сами, поэтому обновляйте `ros-qtt.conf`.
- Внутри туннеляIPv6 не поддерживается (ядро csqtt — IPv4-only).
